## 项目简介

本项目是一套面向电子爱好者、实验室和小型研发团队的个人电子元件库管理系统，由 WebUI 管理软件和带有位置编号的 3D 打印收纳盒组成。

系统为每种元件登记型号、参数、封装、备注等资料，同时使用 `box_id` 表示收纳盒编号、使用 `pos_id` 表示盒内位置编号。查找元件时，只需在浏览器中搜索，系统便会显示其对应的 `BOX / POS`，随后按照编号从实体收纳盒中取出元件。

本项目希望用尽量简单的方式解决电子元件“有库存却找不到”的问题。当前版本不依赖数据库服务器、无线通信模块或指示灯，部署和复刻成本较低，已经可以满足个人工作台日常的元件管理与取料需求。

## 项目功能

- 元件信息管理：支持元件的新增、编辑和删除；
- 实体货位绑定：每种元件均可登记 `box_id` 和 `pos_id`，与 3D 打印收纳盒上的编号对应；
- 快速修改位置：可直接修改元件的 BOX/POS，也可交换两个元件的存放位置；
- 多字段搜索：支持按名称、型号、参数、封装、备注、料盒编号和位置编号进行筛选；
- 参数范围搜索：能够识别 `R/K/M`、`p/n/u` 等常见电子参数单位，适合按阻值、容值范围查找元件；
- 智能排序：支持按照名称、参数、料盒编号或位置编号排列搜索结果；
- 自动填写位置：新增元件时，可根据当前收纳盒中已使用的最大位置号填写下一个 `pos_id`；
- 立创商城资料抓取：支持使用关键字、立创编号、商品 ID 或商品链接获取型号、品牌、封装、规格参数、数据手册和库存等资料；
- 交互式 BOM 联动：可导入立创EDA离线交互式 BOM，在表格、2D 或 3D 视图中选中器件后，自动匹配本地元件库并显示其 `BOX / POS`；
- 本地化运行：元件资料保存在本机，无需部署独立数据库或连接云端服务。

本项目适用于个人电子工作台、创客空间、学校实验室、维修工作室，以及需要按照 BOM 快速查找元件的小批量研发场景。

## 项目参数

- 系统组成：WebUI 管理软件 + 编号式 3D 打印收纳盒；
- 货位编码：`box_id` 表示收纳盒编号，`pos_id` 表示盒内位置编号；
- 单个收纳盒位置数量：当前模型按照 81 个位置设计；
- Web 后端：Python + Flask + flask-cors；
- Web 前端：原生 HTML、CSS 和 JavaScript；
- 本地数据文件：`components.json`；
- Web 服务默认地址：`http://127.0.0.1:5000/`；
- 元件匹配字段：名称/型号、参数、封装及备注等；
- BOM 格式：立创EDA导出的离线交互式 BOM HTML；
- 机械资料格式：SolidWorks 零件及装配体、STEP、DXF；
- 软件依赖：WebUI 基础功能仅需 Python、Flask 和 flask-cors；
- 可选依赖：使用立创商城关键字搜索时需要安装 Node.js，使用立创编号或商品链接时不受影响。

## 原理解析

本项目的核心思路是建立“数字元件记录”与“实体存放位置”之间的对应关系。

每一种元件在 `components.json` 中保存一条记录，内容包括元件名称、参数、封装、备注、`box_id` 和 `pos_id` 等信息。3D 打印收纳盒上标注相同的位置编号。用户在 WebUI 中搜索元件后，系统返回其 BOX/POS，用户再根据编号找到对应收纳位置。

```text
搜索元件或在 BOM 中选中器件
            ↓
WebUI 根据型号、参数和封装匹配本地记录
            ↓
显示对应的 BOX / POS
            ↓
按照编号在 3D 打印收纳盒中取出元件
```

### 1. 编号式收纳结构

实体部分由多个 3D 打印收纳位置组成。每个收纳盒分配一个唯一的 `box_id`，盒内每个位置分配一个 `pos_id`。例如，界面显示 `BOX 2 / POS 15`，即表示元件存放在 2 号收纳盒的 15 号位置。

这种方式不需要在每个位置安装电子器件，只要确保模型上的编号清晰，并且软件记录与实际摆放一致，即可快速完成定位。仓库的 `Hardware` 目录提供了收纳盒、顶板和合页等 SolidWorks 文件，同时包含 STEP 和 DXF 导出文件，方便按实际需求修改或加工。

### 2. WebUI 元件管理

Web 后端使用 Flask 实现，统一提供元件库增删改查、位置交换、参数范围搜索、立创资料抓取、BOM 上传和智能匹配等接口。前端为单页管理界面，浏览器打开后即可完成元件录入和检索。

所有数据默认保存在 `components.json` 中，因此无需安装 MySQL 等数据库。对于个人元件库而言，本地 JSON 文件便于备份、迁移和手工检查，也降低了部署复杂度。

### 3. 交互式 BOM 联动

系统可载入立创EDA导出的离线交互式 BOM。加载时，后端会向 BOM 页面注入 `bom_bridge.js`。当用户点击 BOM 表格中的器件，或在 2D/3D 视图中选中器件时，桥接脚本会提取其型号、参数和封装，并请求 `/lightup` 匹配接口。

虽然接口名称沿用了早期设计中的 `/lightup`，但当前功能只是查询并返回元件的 `box_id` 和 `pos_id`，不会控制任何指示灯。匹配结果会直接显示在浏览器中，用户按照 BOX/POS 编号取料即可。

### 4. 可选点灯扩展

当前成品版本没有安装货位指示灯，因为实际使用中，通过 WebUI 显示 BOX/POS，再查看收纳盒上的编号，已经能够快速找到元件，也使整体结构更简单、成本更低。

如果后续希望获得更直观的定位效果，也可以在收纳位置旁增加可寻址 LED，并通过控制板点亮目标位置。该点灯方案已经在小型验证板上完成测试，证明扩展思路可行；但它不是当前版本正常使用所必需的组成部分，也不影响 WebUI 和编号式收纳盒的完整功能。

## 软件代码

启动 WebUI：

```bash
cd WebUI
pip install -r requirements.txt
python app.py
```

启动后，在浏览器中访问：

```text
http://127.0.0.1:5000/
```

元件数据的基本结构如下：

```json
{
    "元件名称": {
        "box_id": 1,
        "led_id": 15,
        "parameter": "10K",
        "voltage": "",
        "footprint": "0603",
        "note": "常用贴片电阻"
    }
}
```

> 为兼容项目早期数据，JSON 文件中仍使用字段名 `led_id`，它在当前 WebUI 中等同于 `pos_id`，仅表示实体收纳位置，不代表系统安装了 LED。

查询元件位置的接口示例：

```text
GET /lightup?part_number=元件型号&parameter=10K&footprint=0603
```

返回结果中包含对应位置：

```json
{
    "status": "success",
    "location": {
        "box_id": 1,
        "led_id": 15,
        "pos_id": 15
    }
}
```

完整工程资料包括：

- `WebUI/`：Flask 后端、管理界面、BOM 桥接脚本和元件数据；
- `Hardware/`：3D 打印收纳盒相关的 SolidWorks、STEP 和 DXF 文件；
- `Software/`：经过小板验证的可选点灯扩展代码，不是当前成品版本的必需部分。

## 注意事项

- `box_id`、`pos_id` 与实体收纳盒编号必须保持一致，否则会导致取错位置；
- 项目数据中的 `led_id` 是为兼容早期版本保留的字段，在当前版本中应理解为 `pos_id`；
- 首次使用时，建议先对所有收纳盒和位置进行统一编号，再开始录入元件；
- 调整元件位置后，应及时在 WebUI 中修改 BOX/POS，避免软件记录与实物不一致；
- `components.json` 是本地元件数据库，批量修改、更新程序或迁移电脑前建议备份；
- 上传新的交互式 BOM 会覆盖当前的 `InteractiveBOM_v7.html`，操作前建议备份原文件；
- 不同版本的立创EDA交互式 BOM 页面结构可能变化。如无法识别，可将 `bom_bridge.js` 中的 `DEBUG` 设置为 `true`，并查看浏览器控制台日志；
- 立创商城关键字搜索依赖 Node.js；未安装 Node.js 时，可改用立创编号、商品 ID 或商品链接；
- 3D 打印后应检查编号是否清晰、盒体是否变形、活动结构是否顺畅；
- 点灯功能属于可选扩展，当前 WebUI 和编号式收纳盒不依赖该功能即可正常使用。
